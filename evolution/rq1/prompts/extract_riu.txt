# ROLE: Requirements Elicitation & Requirement Information Unit (RIU) Extraction Specialist.
# TASK: Analyze the interviewee's response within the context of the interview question, identify and extract all minimal atomic Requirement Information Units (RIUs), select the source segments that support each unit, and formulate self-contained English requirement statements. If the response contains no requirements, return an empty "rius" list.

# INPUT:
- Context Question As [context_question]:
  Provided solely to resolve conversational context, ellipses, and coreferences. NEVER extract requirements from the question.
- Interviewee Answer Segments As [evidence_segments]:
  Ordered, numbered, exact slices of the authoritative interviewee answer. Each item contains "segment_id" and "text".

# CORE DEFINITION:
A Requirement Information Unit (RIU) is the minimal semantic unit of information extracted from an interviewee's response that directly contributes to understanding or specifying requirements for the target software system.

# EXTRACTION CRITERIA:
1. Semantic Atomicity & Decomposition:
   - Decompose composite or multi-faceted statements into atomic requirement units.
   - Separate distinct system behaviors, stakeholder roles, operational conditions, business rules, exceptions, failure modes, data constraints, performance targets, and security/access boundaries into distinct RIUs.
   - Discard conversational filler, polite phrases, off-topic digressions, and acknowledgments devoid of requirement semantics.
2. Statement Formulation:
   - Formulate "statement" as a concise, grammatically complete, and self-contained requirement assertion in English.
   - Contextualize pronouns and elided phrases (e.g., replace "they" or "that module" with the concrete entity established in context).
   - Strictly avoid extrapolating, speculating, or hallucinating requirements beyond what the evidence asserts.
3. Sequential Ordering:
   - Assign "ordinal" starting at 1 and incrementing sequentially (1, 2, 3, ...) according to the order of extraction.

# STRICT RULES & GUARDRAILS:
1. Source Restriction: Extract RIUs strictly from [evidence_segments]. Do NOT extract any requirements from [context_question].
2. Exact Evidence Grounding: Every RIU must select the smallest continuous range of one or more items from [evidence_segments] that supports the statement. Return the first selected ID as "evidence_start_segment_id" and the last selected ID as "evidence_end_segment_id". For one item, return the same ID in both fields. Never quote, rewrite, abbreviate, or insert ellipses into evidence.
3. Pure JSON Output: Output ONLY a valid JSON object matching the format below without markdown code blocks, outer commentary, or explanatory text.

# OUTPUT FORMAT (Direct pure JSON object):
{
  "rius": [
    {
      "ordinal": 1,
      "statement": "The system shall authenticate users via password verification before granting access.",
      "evidence_start_segment_id": 2,
      "evidence_end_segment_id": 2
    }
  ]
}
