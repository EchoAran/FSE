# 阶段一：方法规格抽取

## 目标

把论文中公开的信息整理成一份可直接指导编码的 Method Specification。

## 需要整理的内容

### Initial Slots

原论文使用 8 个职业访谈 Slot，每个 Slot 包含：

```json
{
  "category": "...",
  "value": null
}
```

### Dynamic Slot Generation

Prompt 要求：

- 读取 dialogue history；
- 读取 current slots；
- 创建新的、与现有 Slot 不重复的 Slot；
- 一次最多生成 5 个；
- 新 Slot 初始 `value=null`。

### Abduction

Proposed Method 2 输出：

- `Surprising Fact C`
- `Reason to Suspect A`
- `New Slot`

并读取：

- dialogue history；
- current slots；
- abduction history。

### Slot Filling

要求：

- 基于 conversation 更新已有 Slot；
- 不删除 Slot；
- 不在 Slot Filling 阶段创建新 Slot；
- 已有 Slot 可以被补充或更新。

### Question Generation

要求：

- 根据 current slots 选择目标；
- 一次一个问题；
- 问题具体；
- 尽量避免重复；
- 逻辑相关的 Slot 可合并询问。

### 模型

原论文：

- `gpt-4o-2024-05-13`
- temperature = `0.1`

## 未明确项

实施时需要明确处理论文没有给出的内容，例如：

- 多个 candidate target slots 的精确排序；
- JSON parse fail 如何处理；
- DialBB 应用配置；
- 空 Slot 选择 tie-break；
- retry policy。

对这些内容只采用支撑运行的最小决策，不把它们扩展成新算法。如确实形成影响方法忠实性的偏差，只在实施结束后的统一说明文档中补充。

## 验收标准

- 所有 Prompt 已从论文附录转录；
- Method Specification 已覆盖核心运行规则；
- 论文未公开行为没有被扩展为新机制；
- 尚未做 RE 领域修改。
