# 阶段二：核心系统重实现

## 目标

实现一个不依赖完整 DialBB 应用配置的最小 Dynamic Slot + Abduction 系统。

## 最小状态

```python
class Slot:
    name: str
    category: str | list[str]
    value: str | None

class InterviewState:
    slots: dict[str, Slot]
    abduction_history: list[dict]
    dialogue_history: list[Turn]
```

## 推荐每轮执行顺序

依据论文 4.3 与 Appendix A，采用：

```text
receive interviewee answer
        ↓
slot filling
        ↓
dynamic slot generation + abduction
        ↓
merge new slots
        ↓
question generation
        ↓
append interviewer question
```

如果后续获得作者代码证明顺序不同，再按新证据修订。

## JSON 校验

### New Slot

- 必须有 name；
- 必须有 category；
- value 必须为 null；
- 每轮最多 5 个；
- 与已有 Slot 重复则拒绝。

### Slot Filling

- 输出全部 Slots；
- 不允许删除；
- 可更新已有 value；
- 不允许创建新 Slot。

### Question

- 必须返回 Question；
- 必须满足 one-question constraint。

## DialBB

第一版建议不依赖 DialBB。

原因：

- 原论文核心创新不在 DialBB；
- 原 app-level STN 配置未公开；
- 强行使用最新版 DialBB 可能引入不必要偏差。

可在后续增加兼容层，但不要让 DialBB 成为第一版复现的阻塞点。

## 验收标准

- 能连续运行至少 10 轮；
- Slot Filling 正常；
- 至少能触发一次 Dynamic Slot；
- 至少能形成一次 C/A abduction；
- Question Generation 能围绕空 Slot 继续询问；
- 未加入 RE 特有机制。
