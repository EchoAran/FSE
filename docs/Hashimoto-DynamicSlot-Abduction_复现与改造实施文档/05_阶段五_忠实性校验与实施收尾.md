# 阶段五：忠实性校验与实施收尾

## 目标

确认软件需求版系统仍然忠实于 Hashimoto Proposed Method 2。

## 检查 Dynamic Slot

- 新 Slot 是否由对话内容触发；
- 是否避免重复；
- 是否每轮最多 5 个；
- 是否存在合理 category；
- 是否没有引入 Topic 等新层级。

## 检查 Abduction

- 是否只在适合时使用；
- C 与受访者原话有依据；
- A 是合理假设而不是无约束想象；
- New Slot 用于验证 A；
- abduction history 能避免重复。

## 检查 Slot Filling

- 只填已有 Slot；
- 不删除；
- 不在此模块创建新 Slot。

## 检查 Question Generation

- 仍以 Slots 为主要信息组织对象；
- 一轮一个主要问题；
- 不出现新的 scheduler 或 planning module。

## 退出条件

如果实现必须大量自行设计以下内容，说明复现可信度不足：

-复杂 target-slot priority；
- 独立 topic scheduler；
- 大量额外状态类型；
- 依赖未公开 DialBB 配置才能正常运行。

此时应先重新评估实现，而不是继续扩张。

## 实施说明（可选）

如有必要，可在全部实施结束后于本项目根目录统一补充一份 `IMPLEMENTATION_NOTES.md`，只说明实际完成内容、必要偏差与已知限制。

不在代码中增加版本号、哈希、配置快照或专门的追溯元数据。

## 验收标准

- 核心机制与论文一致；
- 领域修改与方法修改完全分离；
- 论文未公开行为没有被扩展为新机制；
- README 可从空环境运行一个软件需求访谈 Case。
