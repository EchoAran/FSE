# 阶段三：RE 领域适配

## 目标

把原护士职业访谈中的领域先验替换为软件需求访谈知识。

## 1. Initial Slot Set

原方法的 Initial Slot Set 是由护理管理者确定的最小职业访谈信息集合。

软件需求访谈版本需要构建一套固定 RE Initial Slot Set。

建议来源：

- Volere Requirements Specification Template；
- IREB Requirements Elicitation；
- ISO/IEC/IEEE 29148；
- 经典 Requirements Engineering 文献。

## 推荐构建原则

Initial Slots 应是高层、跨项目可用的信息关注点，而不是某个具体 Case 的标准答案。

建议候选：

- project goals / problem context；
- stakeholders / user roles；
- functional needs；
- business process / rules；
- data / information；
- constraints / dependencies；
- quality concerns；
- exceptions / boundary conditions。

这些来源用于设计通用的 RE Initial Slots，不另外建立来源映射表。

## 2. Dynamic Slot Prompt

将原领域措辞替换：

```text
career goals
career concerns
specialized skills
personal concerns
```

为 RE 语义，例如：

```text
stakeholder goals
functional or operational needs
constraints
exceptions
quality concerns
business rules
```

## 3. Abduction

保留推断逻辑，但改写领域定义：

- C：受访者表达出的重要异常、限制、风险、需求变化或值得解释的事实；
- A：可能解释该事实的业务原因、约束、前提或潜在需求；
- New Slot：为验证 A 需要进一步获取的信息。

不要把这个过程改造成“冲突检测”或“uncertainty state”。

## 4. Question Persona

把 senior nurse 替换为 experienced requirements analyst。

保留：

- one question；
- specific；
- no repeated question；
- logically related slots 可组合。

## 5. self-assessment

原系统在访谈前接收 self-assessment questionnaire。

软件需求访谈版本将其改为：

`initial_requirements`

它只是访谈开始前已知的项目背景。

## 验收标准

- RE Initial Slots 固定；
- Initial Slots 保持高层且跨项目可用；
- RE Prompt 与原始 Prompt 分开维护；
- 核心算法代码不因领域适配发生变化；
- 原 Dynamic Slot / Abduction 行为仍然有效。
