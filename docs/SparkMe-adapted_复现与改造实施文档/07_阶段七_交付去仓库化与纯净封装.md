# 阶段七：交付去仓库化与纯净封装

## 目标

在方法复现、RE 改造和自动化验收全部完成后，将 `sparkme/` 从源码仓库工作副本收敛为纯净的 SparkMe 需求访谈方法交付目录。

本阶段只处理交付边界和生成物，不修改已经通过验收的 Agent 职责、Prompt、状态模型、rollout、utility 或公共接口。

## 1. 执行时机

去仓库化必须是最后一个实施阶段。

在执行前应完成：

- 阶段一至阶段六的全部实现与验收；
- 核心方法链和内置 Agent 有限回滚探针；
- 全量自动化测试；
- README、依赖清单和示例入口核对；
- 所有仍需借助 Git diff 完成的人工审查。

删除 `.git/` 后，当前目录将失去本地历史、差异和恢复能力，不得再把它当作开发工作副本继续修改。

## 2. 删除范围

从最终 `sparkme/` 交付目录删除：

- `.git/`；
- `.github/`、`.gitignore`、`.gitattributes`、`.gitmodules` 等仓库服务或 Git 专用文件；
- 上游 CI、Issue 模板、PR 模板、仓库徽章和仅服务于仓库协作的配置；
- `.pytest_cache/`、`__pycache__/`、`.pyc`、`.ruff_cache/` 等缓存；
- `tests/`、生产目录中的 Mock/Fake 实现、pytest 依赖和 `--mock` 等测试运行入口；
- `logs/`、`output/`、临时 Transcript、测试日志和运行快照；
- 裁剪后遗留的空目录；
- 已删除实验、基线、模拟受访者、Web、语音和评价模块的残余入口或路径引用。

不要创建代码版本清单、commit 记录、Prompt 哈希、配置快照或来源证明来替代被删除的 Git 元数据。

## 3. 保留范围

最终交付至少保留：

- `src/` 中 SparkMe 方法主链和最小公共接口；
- RE Topic Guide 等正常运行配置；
- 最小示例；
- `README.md`、`.env.example` 和实际依赖清单；
- 依法分发所需的许可证文件。

许可证不是 Git 痕迹，也不是方法来源追溯设施，不应因去仓库化而删除。

## 4. 实施步骤

### 4.1 确认目标目录

- 解析并人工确认待清理目录的绝对路径确为 `sparkme/`；
- 列出根目录和隐藏项，确认 `.git/` 等目标均位于该目录内；
- 禁止使用未解析的环境变量、通配符或上级目录作为递归删除目标。

### 4.2 清理运行生成物

- 在删除开发测试前完成最后一次全量自动化验收；
- 删除缓存、日志、示例输出和临时文件；
- 删除 `tests/`、Mock/Fake 实现和测试专用配置；
- 从生产引擎分发器与示例入口中移除 Mock 分支；
- 从依赖清单中删除 pytest 等测试专用依赖；
- 清理测试运行产生的缓存、日志和输出。

### 4.3 移除仓库痕迹

- 在确认不再需要 Git 差异审查后删除 `.git/`；
- 删除其他 Git 和托管平台专用文件；
- 清理 README 中仅用于克隆、贡献、上游仓库导航或仓库展示的内容；
- 不在代码、Prompt、Transcript 或运行配置中增加任何替代性追溯字段。

### 4.4 收敛交付树

- 按保留范围检查最终文件树；
- 删除无文件的空目录；
- 确认生产模块中不存在 `tests/`、Mock/Fake 或 pytest 引用；
- 确认示例只依赖交付目录中实际保留的方法模块。

## 5. 去仓库化后的验证

由于 `.git/` 已不存在，最终验证不得依赖 `git status` 或 `git diff`，应使用文件系统和运行行为直接验收：

1. 递归列出文件及隐藏项，确认不存在 `.git/`、`.github/` 和 Git 专用文件；
2. 搜索并确认不存在实验、baseline、synthetic user、ground truth、评价和上游产品外壳引用；
3. 搜索代码与 Prompt，确认不存在版本、commit、哈希、来源说明和证据追溯字段；
4. 执行核心包导入检查；
5. 对保留 Python 文件执行语法解析检查；
6. 检查示例 CLI 帮助可正常加载且不再提供 `--mock`；
7. 搜索并确认不存在 `tests/`、Mock/Fake、pytest 依赖和测试专用环境变量；
8. 检查公共 Transcript 数据模型仍只包含 Case、问答轮次和结束状态；
9. 真实模型运行与问题质量由使用者在已安装运行环境中手动验证。

## 6. 验收标准

- 最终目录不再是 Git 工作树，也不包含仓库托管平台元数据；
- 根目录只包含 SparkMe 方法运行、示例和说明所需资产；
- 不存在缓存、日志、输出样例和裁剪遗留空目录；
- 不存在测试目录、Mock/Fake 引擎、pytest 依赖或测试运行入口；
- Agenda、coverage、emergence、rollout、utility、strategic question、有限回滚、正常结束持久化和公共 Transcript 契约已在删除开发测试前完成验收；
- 不存在新增的每轮检查点、Checkpoint/Resume API 或通用事务设施；
- 代码与 Prompt 不承担来源、版本或证据追溯职责。

## 阶段产物

- 去除 Git 与仓库服务痕迹的 `sparkme/` 交付目录；
- 仅保留方法运行资产且不包含测试工具的纯净交付结构；
- 不额外生成版本证据包、哈希清单或配置快照。
