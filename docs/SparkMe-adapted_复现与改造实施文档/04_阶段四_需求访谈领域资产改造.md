# 阶段四：需求访谈领域资产原位改造

## 目标

通过官方源码已有的 Topic Guide、上下文和 Agent Prompt 扩展点，将裁剪后的 SparkMe 改造成软件需求访谈系统。

所有改造直接落在最终运行资产上，不保留 workforce/RE 双套文件。

## 1. RE Topic Guide

用通用软件需求访谈 Guide 替换 `data/configs/topics.json`。建议高层主题覆盖：

1. 项目目标与当前问题；
2. 利益相关者、用户角色与权限；
3. 当前业务流程、使用场景与痛点；
4. 期望能力与功能行为；
5. 数据、接口与外部系统；
6. 业务规则、异常与边界条件；
7. 质量属性与运行约束；
8. 依赖、风险、范围与优先级；
9. 验收期望与尚未确定事项。

Guide 是所有 Case 共用的访谈关注框架，不是 gold answer，也不根据每个 Case 自动生成一套新 Guide。

每个 subtopic 应是可通过访谈逐步覆盖的问题域，避免写成预设结论或实现方案。

## 2. 删除模拟画像，保留最小访谈上下文

删除预制 workforce portrait、模拟人格和 profile loader。

如果官方 Agent 流程需要 portrait 类上下文，则将其收敛为由初始需求和真实回答逐步维护的 stakeholder/project context，例如：

- 利益相关者角色与职责；
- 目标和成功标准；
- 当前流程与痛点；
- 领域术语；
- 已知约束、决策与未决问题。

该上下文不包含隐藏事实、预设回答或 ground truth，不负责模拟受访者。

## 3. Agent Prompt 原位改造

直接改写以下现有 Prompt：

- Interviewer：面向利益相关者提问，追问目标、场景、规则、约束、异常和质量需求；
- Agenda Manager：从回答中更新 RE notes、coverage 与 emergent requirements；
- Exploration Planner：在既有 utility 与 rollout 机制下规划覆盖缺口、追问和新出现的需求主题。

### 必须保留

- Agent 职责边界；
- 现有工具调用契约；
- predefined 与 emergent subtopic 的关系；
- rollout 输入输出结构；
- strategic question 回流机制；
- coverage、cost、emergence 三部分 utility。

### 必须去除或改写

- workforce、职业发展和 AI-at-work 示例；
- 模拟受访者行为说明；
- 将受访者当作带隐藏 profile 的 Agent 的措辞；
- 与论文评价或 baseline 比较有关的说明；
- 机械强制所有问题遵循 STAR 的规则。

需求访谈可对具体事件或工作流使用场景化追问，对目标、规则、数据、约束和质量属性使用描述式追问。不得为了保留 workforce Prompt 而强迫所有 subtopic 收集完整 STAR 四元组。

## 4. Prompt 清洁要求

Prompt 只包含模型执行任务所需的信息：角色、输入、决策规则、工具和输出格式。

Prompt 中不得出现：

- 论文或作者名称；
- Figure、Table、Appendix 等来源标记；
- “原文转录”“官方 Prompt”等说明；
- URL、commit、版本、哈希；
- 为验收或证据追溯服务的元数据；
- 与当前 RE 运行无关的历史注释。

## 5. Initial Requirements 注入

`initial_requirements` 作为当前项目背景注入会话，并对三个 Agent 可见。

它用于：

- 避免脱离项目背景提问；
- 帮助识别当前回答涉及的 Guide subtopic；
- 帮助 planner 预测有意义的追问方向；
- 帮助判断真正的新兴需求主题。

它不用于：

- 生成 gold subtopics；
- 预填全部 coverage；
- 替代受访者回答；
- 修改 utility 公式。

## 验收标准

- 最终只有一套 RE Topic Guide 和一套运行 Prompt；
- 不存在 workforce、synthetic user 或论文来源措辞；
- 三个 Agent 均能获得项目背景；
- Agenda、emergence 与 planner 的方法语义未被改写；
- 原始 workforce 系统不再作为交付能力保留。

## 阶段产物

- RE `topics.json`；
- 最小 stakeholder/project context 配置；
- 原位改造后的三个 Agent Prompt。
