# 阶段六：方法完整性与交付清洁度验收

## 目标

证明最终系统是“官方 SparkMe 方法的干净 RE 改造”，而不是论文实验副本、手写平行实现或带追溯设施的研究代码包。

## 1. 结构验收

确认以下目录或能力不存在：

- baselines；
- dataset generation；
- offline evaluation；
- synthetic user profiles；
- LLM user agent；
- participant study、annotation 和 ground truth；
- baseline prompt mode；
- evaluation logger；
- 非交付所需的 Web、云部署和语音代码。

使用 import 扫描确认保留代码不再引用已删除模块。

## 2. 方法链路验收

通过脚本化 LLM 响应执行多轮集成测试，确认：

- Interviewer 能基于 Agenda 和历史提出问题；
- Agenda Manager 能记录 notes 并更新 predefined coverage；
- 对话中新出现的有效需求主题能加入正确 parent topic；
- Exploration Planner 按正常触发条件执行；
- rollout 的数量和 horizon 来自正常运行配置；
- utility 仍由 coverage gain、cost 和 emergence gain 组成；
- strategic questions 能进入后续提问候选；
- nested tool-call 参数不会丢失；
- 内置 Agent 子阶段异常时，尚未完成的本轮并发任务会被取消；
- 当前保留组件的会话内状态可恢复到本轮开始前，并在有限回滚成功后干净重试。

测试只验证源码行为，不复现论文 coverage、用户研究、专家评分或 baseline 对比结果。

失败测试的边界仅包括当前实现管理的 chat history、Agenda、Memory Bank、Question Bank、Planner state 和 Agent event stream。不得把验收扩展为任意对象深拷贝、外部副作用撤销、进程崩溃恢复或跨进程 ACID；也不要求新增每轮 Checkpoint/Resume 机制。回滚本身失败时应暴露错误并终止当前会话。

## 3. RE 领域验收

- Topic Guide 覆盖目标、角色、流程、功能、数据、规则、异常、质量属性、约束、风险和验收；
- initial requirements 对 Interviewer、Agenda Manager 和 Planner 均可见；
- Prompt 中不再出现 workforce、AI-at-work、职业生涯或模拟受访者内容；
- Prompt 不强制所有需求主题使用 STAR；
- emergent subtopic 表达新的需求关注点，而不是普通同义改写；
- 不存在 RE 专用新 utility 或第二套调度器。

## 4. 接口验收

- 初始化、首问、step、结束状态和 Transcript 可由外部程序调用；
- 不依赖 terminal input、UserAgent、Web session 或语音设施；
- 同一回答不会生成重复 Turn；
- 内置方法组件失败且有限回滚成功后可干净重试；回滚失败时不承诺继续当前会话；
- Transcript 不包含内部规划、实验评价和追溯元数据。

## 5. 清洁度验收

全局搜索并处理：

- `baseline`、`synthetic`、`ground_truth`、`evaluation`、`workbank`；
- `user_agent`、`dummy_participant`、profile 数据路径；
- workforce 与 AI-at-work 领域词；
- Prompt 中的 paper、Figure、Appendix、source、URL；
- 版本、commit、hash、配置快照与证据追溯字段；
- 无用依赖、缓存、日志样例和生成产物。

命中项若属于正常方法概念，例如 runtime coverage evaluator，必须人工判断，不能只按关键词机械删除。

## 6. 测试边界

自动化验收使用 mock/fake LLM，覆盖确定性的状态和数据契约。真实模型质量、模型凭证和本地环境安装不作为自动化阻塞项，可由使用者另行手动验证。自动化测试与 Mock 是开发期验收工具，验收结论形成后不保留在最终 `sparkme/` 交付目录中。

## 最终验收标准

- 官方源码方法链被直接复用，没有手写平行实现；
- 实验、模拟受访者和离线评价资产已彻底脱离；
- RE 改造仅改变领域资产与外部接口；
- Agenda、coverage、emergence、rollout、utility 和 strategic planning 均有自动化行为证据；
- 失败处理保持为内置方法组件的会话内有限回滚，不演化为通用事务或跨进程恢复系统；
- 代码与 Prompt 干净，不承担来源或证据追溯职责；
- 项目可作为独立的软件需求访谈组件使用。

## 阶段产物

- 自动化测试结果；
- 精简后的运行说明；
- 如确有必要，实施结束后在单独文档中简述必要偏差和已知限制，不向代码或 Prompt 回填来源信息。
