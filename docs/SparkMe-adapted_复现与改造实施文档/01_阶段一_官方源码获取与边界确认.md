# 阶段一：官方源码获取与资产边界确认

## 目标

直接取得 SparkMe 官方源码，并以仓库中的现有实现作为后续裁剪和改造基线。

本阶段不根据论文创建类、状态模型、Prompt 或算法实现。

## 实施动作

将官方仓库下载到项目的 `sparkme/` 目录：

```bash
git clone https://github.com/SALT-NLP/SparkMe.git sparkme
```

如果 `sparkme/` 已是空目录，可直接将仓库内容下载到该目录。完成后先做目录和 import 依赖清点，不安装完整实验环境，不执行数据生成或论文评价。

## 资产分类

### 方法核心候选

- `src/agents/interviewer/`
- `src/agents/agenda_manager/`
- `src/agents/exploration_planner/`
- `src/agents/base_agent.py`
- `src/content/session_agenda/`
- `src/content/memory_bank/`
- `src/content/question_bank/`
- `src/content/embeddings/`
- `src/interview_session/` 中的会话编排与消息模型
- `src/utils/llm/` 及方法运行必需的少量工具

### 明确排除候选

- `baselines/`
- `dataset_gen/`
- `evaluation/`
- `data/workbank_seed/`
- `data/sample_user_profiles/`
- `scripts/annotations/`
- `src/agents/user/`
- 模拟受访者、评价日志、用户研究与实验统计相关文件
- 非最终交付所需的 Web、云部署、语音和展示资产

### 需要在裁剪时判断的共享设施

- Session Logger；
- Token Tracker；
- Memory Bank；
- Question Bank；
- Embedding Service；
- Topic completion evaluator；
- `Participant` 消息订阅抽象。

判断标准是“是否被 SparkMe 方法运行真实依赖”，而不是文件名是否带有 user、participant 或 evaluator。内部消息参与者抽象与运行时 coverage 判定可属于方法；模拟人格和离线评分不属于方法。

## 禁止事项

- 不从论文手写一个新的 SparkMe；
- 不先复制官方 Prompt 到 `prompts_original/` 再另建一套 RE Prompt；
- 不下载或保留 synthetic users、ground truth、baseline logs 和评价结果；
- 不在代码、Prompt 或配置中写来源说明、版本、commit 或哈希；
- 不把仓库历史或论文实验参数变成运行时证据字段。

## 验收标准

- `sparkme/` 中存在完整官方源码，可供后续裁剪；
- 已按“保留、删除、共享依赖”完成清点；
- 尚未重写任何方法算法；
- 尚未引入 RE 自定义状态机；
- 后续删除顺序以 import 依赖为依据，不采用直接删目录后再逐个救火的方式。

## 阶段产物

- 下载后的官方源码；
- 一份实施时使用的资产处置清单，可直接写入任务记录，不进入运行时代码。
