# 阶段二：方法代码提取与交付裁剪

## 目标

从官方仓库中得到一个只包含 SparkMe 方法及最小运行基础设施的代码库。

本阶段不是复跑论文实验，也不要求用 LLM user agent 完成固定轮数访谈。

## 1. 先解除实验耦合

官方源码中的核心会话模块直接导入了模拟受访者和 Evaluation Logger。删除目录前应先移除这些调用关系：

- 去掉 `UserAgent` 与 agent interaction mode；
- 去掉 `UserDummyParticipant`，由干净的回答提交接口代替；
- 去掉 `EvaluationLogger` 初始化和问题相似度评价日志写入；
- 去掉 `EVAL_MODE`、`USER_AGENT_PROFILES_DIR` 等实验配置；
- 去掉 baseline prompt 分支、`USE_BASELINE_PROMPT` 和 `use_baseline` 控制流；
- 保留问题去重行为本身，只删除为论文评价保存 Prompt/Response 的旁路日志。

真实受访者的回答仍作为普通输入消息进入会话，不再由仓库内的模拟 Agent 生成。

## 2. 删除非方法目录

解除依赖后删除：

- `baselines/`；
- `dataset_gen/`；
- `evaluation/`；
- `data/workbank_seed/`；
- `data/sample_user_profiles/`；
- `scripts/annotations/`；
- `src/agents/user/`；
- `src/utils/logger/evaluation_logger.py`；
- 仅服务于实验、标注和参与者统计的输出逻辑。

若最终交付只需要库接口和最小 CLI，同时删除：

- `src/main_flask.py`；
- `src/web/`；
- `scripts/web_interview/`；
- `src/utils/speech/`；
- 与 Web、GCP、AWS、认证、语音相关的依赖和环境变量；
- 仅用于项目展示的 `assets/`。

## 3. 保留共享方法设施

以下内容虽然不是三个 Agent 本体，但被方法链路使用，不能误删：

- Session Agenda 与 Topic Manager；
- runtime topic coverage/completion 判断；
- Memory Bank 与 recall；
- Question Bank、问题去重与 strategic question 存储；
- Embedding Service；
- XML tool-call 解析；
- 会话消息、事件分发和必要的并发控制；
- 方法状态的正常持久化能力。

可以精简普通执行日志，但不得删除 Agenda、coverage、emergence、rollout 等运行状态。

## 4. 收敛入口与依赖

- 只保留一个最小库接口；
- 可附带一个文本 CLI 作为演示，但 CLI 不承载方法逻辑；
- 删除 `--user_agent`、voice、实验模式和论文评价参数；
- 根据保留代码的实际 import 重写 `requirements.txt`；
- `.env_sample` 只保留模型、Embedding、必要目录和正常运行参数；
- 清除重复或已失效的配置项，例如未被源码读取的变量；
- 将 `.env_sample` 中的 `EXPLORATION_PLANNER_TURN_TRIGGER_MIN` 与源码实际读取的 `EXPLORATION_PLANNER_TURN_TRIGGER` 收敛为一个有效名称，并清理重复的 `MODEL_NAME`；
- 不把论文主实验参数强制写成产品默认值，运行语义以保留下来的官方方法实现为准。

## 5. 原始 workforce 资产处理

不需要长期保留 workforce 可运行副本。

在进入阶段四前可短暂使用原配置做结构性检查，但交付时应：

- 用 RE Topic Guide 替换 `data/configs/topics.json`；
- 删除重复的 workforce `script.json`；
- 删除原 workforce portrait；
- 原位改写现有 Agent Prompt；
- 不建立 `topics_original.json`、`topics_re.json` 或双套 Prompt 目录。

## 验收标准

- 排除目录和模块已删除；
- `rg` 检查不存在对已删除模块的 import；
- 不存在 simulated user、baseline mode、evaluation logger 的运行路径；
- 核心方法模块仍可导入；
- Agenda、Memory、Question Bank、Emergence、Planner 的依赖保持闭合；
- 依赖清单不再包含仅为 Web、语音、标注、数据生成或论文评价服务的包。

## 阶段产物

- 裁剪后的 SparkMe 方法代码；
- 最小运行入口；
- 收敛后的依赖与环境配置。
